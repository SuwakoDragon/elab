# 教学 LuCI 故障实验项目交接手册（维护者版）

这份文档给后续维护者使用，目标是把下面三件事稳定传下去：

1. 统一开发与发布工作栈
2. 快速复现构建、部署、验收流程
3. 遇到故障时有一套可执行的排障命令

---

## 1. 项目定位与当前功能边界

项目用于教学场景下的家庭网络故障仿真实验，核心故障类型：

- DNS 配置错误
- DHCP 分配异常
- WAN IP 配置错误
- 默认网关错误

当前实现遵循“低门槛、可回退、可复现”：

- 页面提供故障注入类型选择
- 支持一键注入、一键回退
- 脚本首次注入自动做配置快照
- 提供基础检测入口，便于课堂演示

---

## 2. 工作栈（务必保持版本一致）

### 开发与测试分层

1. Windows 主机
用途：改代码、PowerShell 上传、WinSCP 手工传包。

2. WSL（建议 Ubuntu）
用途：OpenWrt 编译栈构建与生成 ipk。

3. VMware OpenWrt 测试机（x86_64）
用途：安装、运行、验收、课堂测试。

### 技术栈

- LuCI：Lua Controller + CBI Model + View
- OpenWrt 配置层：UCI
- 后端脚本：POSIX Shell
- 服务：uhttpd、rpcd、dnsmasq、network
- 安装：opkg

### 目录职责

- version1/luasrc/controller/experiment.lua
	- 菜单入口与后端接口注册
- version1/luasrc/model/cbi/experiment.lua
	- 实验页主逻辑与交互
- version1/root/usr/bin/inject_experiment_fault.sh
	- 故障注入和快照保存
- version1/root/usr/bin/reset_experiment.sh
	- 快照回滚恢复
- version1/root/usr/share/rpcd/acl.d/luci-app-experiment.json
	- rpcd ACL 权限
- version1/root/etc/config/experiment
	- 实验默认配置
- version1/Makefile
	- 包定义与依赖声明

## 3. 日常开发流程（推荐）

### 第一步：Windows 修改源码

建议每次改动只动一个功能点，便于定位问题。

### 第二步：同步到 WSL 编译树

```bash
cd ~/openwrt/openwrt-24.10
mkdir -p package/luci-theme-elab package/luci-app-experiment

rsync -a --delete /mnt/c/Users/Dragon/Desktop/luci-theme-elab/ package/luci-theme-elab/
rsync -a --delete /mnt/c/Users/Dragon/Desktop/version1/ package/luci-app-experiment/
```

无 rsync 时可用：

```bash
cp -a /mnt/c/Users/Dragon/Desktop/luci-theme-elab/. ~/openwrt/openwrt-24.10/package/luci-theme-elab/
cp -a /mnt/c/Users/Dragon/Desktop/version1/. ~/openwrt/openwrt-24.10/package/luci-app-experiment/
```

### 第三步：编译

```bash
cd ~/openwrt/openwrt-24.10
./scripts/feeds update -a
./scripts/feeds install -a
make defconfig

make package/luci-theme-elab/compile V=s
make package/luci-app-experiment/compile V=s
```

查找产物：

```bash
find ~/openwrt/openwrt-24.10/bin/packages -type f -name "luci-theme-elab*.ipk" | sort
find ~/openwrt/openwrt-24.10/bin/packages -type f -name "luci-app-experiment*.ipk" | sort
```

## 4. 部署路径 A（首选：ipk 安装）

### PowerShell 一键安装（推荐）

```powershell
$OWRT_IP="192.168.2.2"
$OWRT_USER="root"

$PKG1=(wsl bash -lc "find ~/openwrt/openwrt-24.10/bin/packages -type f -name 'luci-app-experiment*.ipk' | sort | tail -n 1").Trim()
$PKG2=(wsl bash -lc "find ~/openwrt/openwrt-24.10/bin/packages -type f -name 'luci-theme-elab*.ipk' | sort | tail -n 1").Trim()

if([string]::IsNullOrWhiteSpace($PKG1)){ Write-Error "未找到 luci-app-experiment*.ipk"; exit 1 }
if([string]::IsNullOrWhiteSpace($PKG2)){ Write-Error "未找到 luci-theme-elab*.ipk"; exit 1 }

wsl bash -lc "cp '$PKG1' /mnt/c/Users/Dragon/Desktop/ ; cp '$PKG2' /mnt/c/Users/Dragon/Desktop/"

$F1=[System.IO.Path]::GetFileName($PKG1)
$F2=[System.IO.Path]::GetFileName($PKG2)

scp "C:\Users\Dragon\Desktop\$F1" "C:\Users\Dragon\Desktop\$F2" "${OWRT_USER}@${OWRT_IP}:/tmp/"
ssh "${OWRT_USER}@${OWRT_IP}" "opkg install --force-reinstall /tmp/$F1 /tmp/$F2; /etc/init.d/rpcd restart; /etc/init.d/uhttpd restart"

Write-Host "完成：已安装 $F1 和 $F2"
```

## 5. 部署路径 B（兜底：源码直拷）

当编译树或依赖异常，临时采用源码直拷验证功能：

1. 用 WinSCP 把 version1 整包传到测试机 /tmp/version1
2. SSH 登录后执行：

```sh
cp -f /tmp/version1/luasrc/controller/experiment.lua /usr/lib/lua/luci/controller/
cp -f /tmp/version1/luasrc/model/cbi/experiment.lua /usr/lib/lua/luci/model/cbi/
mkdir -p /usr/lib/lua/luci/view/experiment
cp -f /tmp/version1/root/usr/lib/lua/luci/view/experiment/main.htm /usr/lib/lua/luci/view/experiment/

cp -f /tmp/version1/root/usr/bin/inject_experiment_fault.sh /usr/bin/
cp -f /tmp/version1/root/usr/bin/reset_experiment.sh /usr/bin/
chmod +x /usr/bin/inject_experiment_fault.sh /usr/bin/reset_experiment.sh

mkdir -p /www/luci-static/resources
cp -f /tmp/version1/root/www/luci-static/resources/experiment.js /www/luci-static/resources/

mkdir -p /usr/share/rpcd/acl.d
cp -f /tmp/version1/root/usr/share/rpcd/acl.d/luci-app-experiment.json /usr/share/rpcd/acl.d/

mkdir -p /etc/config
cp -f /tmp/version1/root/etc/config/experiment /etc/config/

rm -rf /tmp/luci-indexcache /tmp/luci-modulecache
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

这条路径用于调试，不建议作为正式发布方案。

## 6. 验收清单（每次发布都跑）

1. LuCI 首页可正常打开，无 Runtime Error
2. 进入 管理后台 -> 网络 -> 实验页面 正常
3. 四类故障都可注入
4. 回退后网络恢复
5. 至少完成一次“注入 -> 检测 -> 修复 -> 再检测”闭环

## 7. 高频排障命令（直接可用）

### 包与依赖

```sh
opkg update
opkg list-installed | grep -E "luci-base|luci-lua-runtime|luci-compat|liblucihttp"
```

### LuCI 运行与日志

```sh
logread -e uhttpd -e rpcd -e luci -e lua
ls -l /usr/lib/lua/lucihttp.so
```

### 接口与脚本检查

```sh
which inject_experiment_fault.sh
which reset_experiment.sh
sh -n /usr/bin/inject_experiment_fault.sh
sh -n /usr/bin/reset_experiment.sh
```

### 缓存与服务重启

```sh
rm -rf /tmp/luci-indexcache /tmp/luci-modulecache
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
```

## 8. 常见坑位速查

1. WSL 能编译但不能 ssh/scp
处理：优先改用 Windows PowerShell 执行 ssh/scp，或 WinSCP 直传 /tmp。

2. zsh 报 no matches found: C:\...
处理：WSL 下必须用 /mnt/c/... 路径，C:\... 只在 PowerShell 用。

3. opkg 报架构不兼容
处理：确认编译目标与测试机一致（x86_64）。

4. 页面显示响应解析失败
处理：先看浏览器 Network 返回的是不是 HTML 错误页，再查 logread 定位后端异常。

5. Lua controller 存在但提示无 Lua runtime
处理：补齐 luci-lua-runtime 与相关 LuCI 依赖，再重启 rpcd/uhttpd。

---

## 9. 维护约定（建议执行）

1. 每次改动先在 VMware 做快照
2. 每次提交附最小复现实验步骤
3. 修改脚本时必须先 sh -n 语法检查
4. 修改 Controller 或 CBI 后必须清 LuCI 缓存
5. 正式给学生使用前，至少做一轮完整课堂流程演练
